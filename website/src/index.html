Quick setup.

One short file per repository, and one that names them. You never list the calls between them: Lemma infers those from OpenAPI documents and code.

Quickstart ↗

See beyond the changed repo.

Billing changed its contract, and nobody declared the link to web. No requirements written. Lemma read the call in web’s code and saw it breaks.

That gives the agent a focused path through a large codebase: what depends on the change and where the relevant code lives.

calls is the call graph Lemma inferred. This warns on every call to an operation in Deprecated.

Keep that intent alongside the code, so every agent works against the same declared requirements.

Declared requirements ↗

Some breaks pass every check.

When billing declines a charge, it tells orders whether the customer may retry, and orders passes that on to its caller. Then an agent tidies orders’ error handling into one helper. The helper builds every error body the same way, and retriable isn’t in it.

Every schema still matches, so contract checks pass. The caller can no longer tell a temporary decline from a final one, and that only shows when the code runs.

Simulate the failure. Verify the fix.

Declare a behavior, and Lemma catches that change before it merges by running the code. Its checker is a script you write: it fakes a declined charge, calls place_order, and reports what orders sent back. The behavior runs it for both answers billing can give, so a fix that hard-codes the flag still fails.

With the change, retriable is missing from orders’ response in both cases. The agent gets that missing field, adds retriable to the helper, and reruns the check. With the fix, it matches billing’s answer in both.Illustrative replay · evidence is kept until the code it ran on changes.
